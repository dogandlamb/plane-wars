# 重构与审查处理

本轮按《Clean Code》《Clean Architecture》《The Pragmatic Programmer》的原则审查可读性、依赖方向、可验证性和改动成本。原始工程保留在原位置，开发在副本中进行。

| 原则 | 代码中的落点 | 验证 |
| --- | --- | --- |
| 清楚的命名和单一职责 | 战斗导演、武器、夜班、快照、绘制、音频分别负责自己的行为 | 核心规则与显示适配分别运行 JVM 检查 |
| 核心不依赖平台 | `shared/core` 不导入 Android；手机和独立服务端复用同一引擎 | Android 构建与 Java 11 服务端分别编译 |
| 在边界验证输入 | 长度、版本、有限数值、房间身份和 TLS 主机名检查 | 畸形消息、身份伪造、错误主机名和慢速连接测试 |
| 单一事实来源 | 三难度共用关卡目录；单机与联机共用规则；客户端不决定碰撞和得分 | 运行到实际刷敌后的离线/服务端状态比对 |
| 方便复现与观察 | 原创音频生成器、独立服务器脚本、验证脚本、明确断线提示 | 真实 socket 与双 Android 客户端记录 |
| 避免重复与多余抽象 | 玩家名称、色彩和音效常量统一；无需 Android 注入框架 | 简化后保留原有证明测试，新行为补独立回归 |

审查覆盖正确性、安全、可靠性、测试、维护性、性能、API 契约和联机战役流程。审查基准为本地 `6666e4c` 到 `f653934`；后续按发现逐项修复并重新构建、验证。

## 已处理的问题

1. 不完整网络消息可能长期占住连接槽位。现使用接受连接到 HELLO 的绝对截止，以及整条消息开始后的绝对接收截止；持续慢速发送也不能延长。新增慢滴、TLS 停滞和 32 槽位回收回归。
2. 联机通关或重试曾回到大厅。现保留房间与成员，用结果确认屏障推进关卡或重试，并重新播放剧情、等待双方就绪。新增真实完整关卡和即时重试测试。
3. 先就绪的玩家切后台，暂停可能丢失。现按成员保存后台状态，覆盖剧情与准备阶段；普通恢复不能解除另一位成员的后台暂停。
4. 大厅断开后曾残留旧房间与出发按钮。现清空房间卡、隐藏并禁用出发，允许重新连接；连接回调带会话与尝试编号，旧回调不能污染新连接。
5. 20 Hz 网络位置直接绘制会有阶梯感。现按稳定实体 ID 做有界显示插值，暂停、重开、换关和较大断档时重置；不外推、不改变权威状态。新增 55 项坐标与边界检查。
6. 本地会话检查曾未进入常规验证。现 `app:check` 会执行真实调度暂停/恢复/关闭检查和插值检查。
7. 最终真实长测出现发送超时误关。检查确认计时字段被连续读取两次，发送线程在中间清零时可能形成 `now - 0`；现对 volatile 字段只读一次，使用同一个局部值判断。原失败记录保留，修复后的完整关卡、常规检查及 TLS 检查全部重跑通过。
8. 收尾检查发现断线后的已排队回调和本地服务器发布窗口。断线或连接失败现使连接编号失效；会话退出和资源发布使用同一个所有权锁，避免刚返回基地又留下后台服务。
9. API 37 双端实测两次发现切后台约 6.5 秒后，系统仍在保留进程的情况下主动销毁该 UID 的 TCP 连接。新增仅在用户主动联机期间运行的前台房间服务，退出、连接失败或断线即停止；不修改系统策略，不请求额外通知弹窗，不使用唤醒锁。声明 `specialUse` 及具体用途，兼容 API 26–33，API 34 以上显式指定类型。依据：[Android 前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types#special-use)、[通知权限说明](https://developer.android.com/develop/ui/views/notifications/notification-permission)。后台连接的最终设备复测单独记录，不以编译代替。
10. 首位玩家看完剧情后，等待画面曾允许无效重打；服务端也会丢弃此时的手动暂停。真实 Android 观察到了卡在等待窗口，新 socket 回归先失败后通过。现在第一帧到来前不显示重打，手动暂停从剧情准备阶段开始保留，未创建引擎时不发送世界帧；合作与比分两种模式均有回归。比分与单人结算后不再显示无法执行的救援提示。
11. 接手复查又确认手机内嵌开房的断线清理遗漏：队友退出后，房主前台服务已停止，但监听 socket 和模拟调度仍在运行。`f6cd86…` 双端实测在退出后仍收到新 HELLO 的大厅回应。现在断线和连接失败先使旧连接编号失效，再在原所有权锁内取走内嵌服务端并关闭。`4eb15c…` 双端完成整晚后由队友先退出，原监听不再回应，两端前台服务均消失；等待、合作续关及比分重试也在新包重新验证。完整记录按 APK 哈希分目录保留，不沿用旧包结论。

保留暂停期间的网络状态广播，因为现有客户端契约需要继续收到暂停状态；未在缺少测量依据时修改协议节奏。第六关按用户要求在开发者模式开放，无限资源不改成普通挑战入口。

## 验证边界

代码审查不等于设备验收。自动规则测试、双模拟器体验、公网部署和实体手机性能分别记录在验收报告中；没有服务器和实体手机的项目不会记为通过。

## 2.1 增量审查（2026-11-13）

前五关的波次压缩到45秒，Boss血量按短关重新配置。审查发现光波可能跳过短Boss的二阶段，已修复为跨过半血时进入二阶段，并保留至少三秒二阶段攻击窗口；新增实际技能路径回归和十五种关卡/难度的模拟检查。无尽模式的时长与Boss数值保留。

普通第六关同时检查菜单、非连续选关编号、开房参数和服务端；平板状态进入权威快照，单机、内嵌开房、独立服务端复用。发布构建不再要求公开源码附带私钥，白名单导出脚本仅保留源码、素材、文档、构建入口与一份正式APK。

已知兼容性限制：旧2.0客户端连接新协议服务端会断开，只显示普通断线，没有专门的升级提示。交付客户端和服务端须一起升级。
